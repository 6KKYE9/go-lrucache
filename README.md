# go-lrucache

这种边角活儿天天干，写一次工具省下往后所有时间。

带过期时间的 LRU 缓存，零依赖，只用标准库。命令行是个交互壳子，核心的 `lru.go` 可以直接抠出来用。

## 编译

```
go build -o go-lrucache.exe
```

## 用法

从标准输入读命令，一行一条：

```
> go-lrucache -cap 2
set a 1
OK
set b 2
OK
get a
1
set c 3
OK
get b
(没有)
stats
条目 2/2  命中 1  未命中 1  命中率 50.0%  淘汰 1  过期 0
```

`b` 没了是因为容量只有 2，而 `a` 刚被读过，所以最久没碰的 `b` 被淘汰。

给所有写入加默认过期时间：

```
go-lrucache -cap 100 -ttl 30s
```

## 支持的命令

| 命令 | 说明 |
|------|------|
| `set <键> <值>` | 写入，值里可以带空格 |
| `get <键>` | 读取，会把这个键提到最近使用 |
| `has <键>` | 只看在不在，不影响 LRU 顺序，也不算进命中率 |
| `del <键>` | 删除 |
| `keys` | 按最近使用顺序列出所有键 |
| `purge` | 主动清掉已过期的 |
| `clear` | 全清 |
| `resize <数字>` | 调整容量，调小会立刻淘汰多出来的 |
| `stats` | 命中率、淘汰数、过期数 |
| `quit` | 退出 |

以 `#` 开头的行当注释跳过，方便写成脚本文件喂进去。

## 实现上注意的几点

- **过期的条目在 `Get` 时会真删掉**，不是只返回 miss。不然一堆过期数据会一直占着容量，新数据反而被挤走。
- **`Len` 和 `Keys` 都跳过已过期的**，返回的是实际还能用的数量。
- **重复 `set` 同一个键只占一个位置**，就地改值再提到队头。
- **`has` 故意不动 LRU 顺序**，探测型的检查不应该影响淘汰决策。
- **`resize` 调小时立刻淘汰**，不会等到下次写入才处理。
